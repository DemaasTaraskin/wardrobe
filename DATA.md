## 0. Решения, на которых всё держится

| Решение | Как есть |
|---|---|
| Состав лука | фиксированные слоты: база · 2-й слой · верхняя одежда · низ · обувь · аксессуар |
| Дождь | на экране подбора есть галочка «дождь». Лук годится в дождь, если **в нём есть рукава** — зонт решает остальное. Непромокаемые верх и обувь желательны, но не обязательны |
| Оценка | 👎 — 6 быстрых причин + комментарий; ❤️ — только комментарий |
| Статус вещи | активна · архив (вне сезона) · на аут; `archived` проставляю я на этапе 2 |
| Температура | банды по 5°, текущий сезон +5…+20 → три банда; 0…+5 добавим отдельной партией, когда похолодает |
| Кто пишет луки | Claude Code через скил; в приложении вызовов Claude нет |

## 1. Справочники

**Ситуации** (5): `gym` спортзал · `dog` собака/район · `office` офис · `weekend` выходные в городе · `evening` вечерний выход.

**Температурные банды** текущего сезона: `+5…+10` · `+10…+15` · `+15…+20`. Границы включительно с обеих сторон: температура ровно +10 попадает в два банда сразу, и это нормально — покажем луки обоих.

**Слоты лука**:

| Слот | Обязателен | Пример |
|---|---|---|
| `base` база | да | футболка, лонгслив, джемпер |
| `layer2` 2-й слой | нет | рубашка поверх футболки, пиджак, безрукавка |
| `outer` верхняя одежда | нет (обязателен при ≤ +15) | бомбер, куртка, пальто |
| `bottom` низ | да | джинсы, брюки, шорты |
| `shoes` обувь | да | кроссовки, ботинки, туфли |
| `accessory` аксессуар | нет, до 2 шт. | сумка, кепка |

**Категории вещи и в каких слотах она может стоять**:

| Категория | Слоты |
|---|---|
| `tshirt` футболка, `longsleeve` лонгслив, `polo` поло | base |
| `shirt` рубашка | base, layer2 |
| `sweater` джемпер/свитер, `sweatshirt` свитшот | base, layer2 |
| `hoodie` худи / джемпер на молнии | base, layer2, outer |
| `vest` безрукавка, жилет | layer2 |
| `blazer` пиджак | layer2, outer |
| `jacket` куртка, `coat` пальто | outer |
| `jeans` джинсы, `trousers` брюки, `shorts` шорты, `sweatpants` спортивные штаны | bottom |
| `shoes` обувь | shoes |
| `accessory` аксессуар | accessory |

Костюм с доски (группа «Костюмы») разбирается на две карточки: `blazer` + `trousers`, со ссылкой друг на друга в `notes`.

**Формальность** — шкала 1–4: `1` домашнее/спортивное · `2` неформальное · `3` smart casual · `4` официальное. У вещи хранится диапазон (`formality_min`…`formality_max`), потому что подписи на доске именно такие: «выходного дня / официальные» = 3–4.

**Цвета** (фиксированная палитра, 1–3 на вещь): `black` `white` `ecru` молочный · `grey` `navy` `indigo` `blue` `teal` тёмная бирюза · `olive` `khaki` `green` `beige` `brown` `burgundy` `red` `yellow` `pink` `purple` `multi`.

**Узор**: `solid` однотонная · `stripe` · `check` клетка · `print` принт/лого · `texture` фактура без цветового рисунка (рубчик, вязка).

**Статус вещи**: `active` · `archived` вне текущего сезона, в подбор не идёт · `out` на аут.

**Причины к оценке** (6): `hot` жарко · `cold` холодно · `wrong_situation` не по ситуации · `colors` цвета не дружат · `not_my_style` не мой стиль · `uncomfortable` неудобно.

### `look_items` — состав лука
`look_id` · `item_id` · `slot` · `position` (0 или 1, только для аксессуаров). Первичный ключ — `(look_id, slot, position)`: два предмета в одном слоте физически не вставить.

### `gaps` — «чего не хватило»
`id` · `user_id` · `season` · `situation` · `temp_min` · `temp_max` · `rain_ok` · `missing` (текст: «на +10…+15 в дождь нет непромокаемой куртки») · `created_at`.
Отдельная таблица, а не поле у лука: пустая ячейка — это когда лука **нет вообще**, записывать пробел некуда.

### `ratings` — оценка
`id` · `user_id` · `look_id` · `verdict` (`love` / `dislike`) · `reasons` enum[] · `comment` text · `created_at` · `updated_at`.
Одна оценка на лук: повторная нажимается поверх старой (`unique (user_id, look_id)`). Историю мнений не храним — для разбора на этапе 6 важно последнее.
Шесть причин показываются только при 👎 — они все про то, что не так. При ❤️ на экране одно необязательное поле комментария, оценка ставится в одно касание.

### `wear_log` — «надел сегодня»
`id` · `user_id` · `look_id` · `worn_on` date · `temp_c` int · `situation` · `rain` bool · `created_at`.
`unique (user_id, look_id, worn_on)` — двойное нажатие не задваивает день. Температура и ситуация пишутся те, что были в подборе: по ним на этапе 6 видно, совпал ли подбор с реальностью.

### `profiles`
`id` (= `auth.uid()`) · `display_name` · `current_season` (`2026-autumn`) · `created_at`.

## 3. Правила доступа

- **Вход** — код на почту, без паролей.
- **Только по приглашению:** самостоятельная регистрация в Supabase выключена. Аккаунт заводишь ты в панели проекта (Invite user) — сначала себе, на этапе 7 второму человеку. Чужая почта войти не сможет, даже зная адрес сайта.
- **Каждая строка принадлежит своему пользователю.** На всех таблицах включён RLS, политика одна и та же: читать, писать, править и удалять можно только строки, где `user_id = auth.uid()`; при вставке это же значение проверяется дополнительно. Общих таблиц и общих луков в v1 нет.
- **Ключ в сайте** — publishable (anon). Он публичен по замыслу, вся защита в RLS; поэтому репозиторий может оставаться публичным. `service_role` не попадает ни в сайт, ни в git — он нам вообще не нужен: миграцию ты выполняешь в SQL-редакторе Supabase.
- **Скил пишет от твоего имени:** один раз запрашивает код на почту, ты присылаешь код в чат, сессия сохраняется в `.supabase-session.json` (в `.gitignore`) и дальше обновляется сама. Пароли нигде не участвуют, и у второго пользователя своя сессия — мои и его строки не пересекаются.
- **Проверка на этапе 7:** запрос ко всем таблицам без фильтра из-под второго аккаунта должен вернуть только его строки.

## 5. Как приложение подбирает луки

1. Ввожу температуру `t`, выбираю ситуацию, при необходимости ставлю галочку «дождь».
2. Берутся активные луки текущего сезона, где `situation` совпадает и `temp_min ≤ t ≤ temp_max`; при галочке — только `rain_ok`.
3. Показываются 2–3 лука. Если подошло меньше двух — добавляются луки соседнего банда с пометкой «на границе диапазона».
4. Если не нашлось ничего, показывается запись из `gaps` для этой ячейки: чего именно не хватает в гардеробе.

Дождь **не удваивает** партию луков: в каждой ячейке (ситуация × банд) я стараюсь собрать хотя бы один лук с `rain_ok`. Условие одно — рукава: в дождь владелец не хочет оказаться в майке или безрукавке, а от воды спасает зонт. Непромокаемые куртка-плащ Columbia и ботинки Timberland идут в такие луки первым номером, но их отсутствие ячейку не закрывает. Объём этапа 5 остаётся прежним: 30–45 луков.
`wind_resistant` в v1 только хранится, на экран подбора не выносится.

## 6. Команды скила `wardrobe-stylist`

| Команда | Что делает | Что на выходе |
|---|---|---|
| `wardrobe push` | берёт локальный `wardrobe.json` и папку с фото, сжимает картинки, заливает в бакет, создаёт и обновляет карточки вещей | сколько добавлено и обновлено, какие фото остались без карточки и наоборот |
| `wardrobe looks <сезон>` | читает активные вещи, `reference_look.md` и `profile.md`, собирает 2–3 лука на каждую ячейку, проверяет правила стиля (палитра, не больше одного принта, слоты заполнены, температурные диапазоны вещей пересекаются), пишет `looks` / `look_items`, пустые ячейки — в `gaps` | таблица покрытия: 5 ситуаций × 3 банда, сколько луков в каждой ячейке |
| `wardrobe feedback` | выгружает оценки и журнал «надел», считает долю ❤️, частые причины отказов и вещи, которые ни разу не вышли из шкафа | сводка в чат + локальный `feedback.md` (в git не попадает) |

`wardrobe push` можно запускать сколько угодно раз: вещь узнаётся по `source_file`, повторный запуск правит карточку, а не создаёт вторую.

## 8. Спорные места и как они решены

| Вопрос | Решение |
|---|---|
| Причины при ❤️ | не показываем, только комментарий — все шесть формулировок про недостатки |
| Нижняя граница температуры | старт с +5; банд 0…+5 генерируем отдельной партией в октябре, уже зная твои оценки |
| Кто отправляет зимнее в архив | я на этапе 2: `archived` всему, чей диапазон не пересекается с +5…+20. Ты правишь точечно в приложении |
| Костюм | классического костюма в гардеробе не оказалось: группа «Костюмы» на доске — это комплекты (спортивный Puma и льняной). Категории `blazer` и `suit` в справочнике остаются, но пока пустые |
| Дождь | флаг у лука, а не отдельная партия луков |
| Формат фото в базе | WebP с прозрачностью вместо PNG — втрое легче при том же виде |

Схема ещё ничего не «заморозила»: до этапа 3 (миграция в Supabase) поменять поле или справочник стоит одну правку в этом файле. После — уже миграция.
